# Decisions

Running log. Add a row when a choice is made that affects the schema, stack, hosting, or scope. Newest at the bottom.

| # | Date | Decision | Options considered | Reason |
|---|---|---|---|---|
| D1 | 2026-10-26 | Web app, installable as a PWA | Native phone app; desktop-only web app | One codebase; phone capture in the basement and laptop review at the desk; browser camera is enough |
| D2 | 2026-10-26 | Run on the Mac laptop first, then a Raspberry Pi home server | Cloud host; Pi from day one | Private, free, nothing to set up before the app exists; Pi is Phase 6 |
| D3 | 2026-10-26 | SQLite file plus a photos folder | Hosted Postgres (Supabase) | Zero infrastructure; backup is a folder copy; full data ownership |
| D4 | 2026-10-26 | Recipes: import Paprika `.paprikarecipes` export in v1; move to self-hosted Mealie (REST API) in Phase 6 | Keep Paprika link-only; AnyList via unofficial API; build recipes into the app | Paprika export format is stable and widely parsed. AnyList has no official API. Mealie is the only option with a documented API and runs on the same Pi |
| D5 | 2026-10-26 | AnyList is out of scope | Push shopping lists later | Grocery tool, not a lab tool; no official API |
| D6 | 2026-10-26 | Readings are manual entry in v1; sensor import designed for but built in Phase 6 | Sensors in Phase 1; manual only forever | Core model first; typed reading table accepts sensor rows later without a schema change |
| D7 | 2026-10-26 | Ferments are the first batch type | Mushrooms; preserves inventory | Tests the protocol snapshot and weekly-log loop with a Paprika recipe immediately. Mushrooms follow in Phase 3 |
| D8 | 2026-10-26 | Standalone app with a clean internal API | First module of a larger "Jarvis" assistant | Ship the thing that gets used in two weeks; a future assistant can read Cellar's data |
| D9 | 2026-10-26 | Name: Cellar. Repo and folder: `cellar` | Root Cellar; Labbook; Basement Lab | Short, covers grow, ferment, and preserves |
| A1 | 2026-10-26 | Single user, no login; home network only | Shared household login; multiple accounts | Nothing to build; revisit only if the Pi is exposed outside the home network |
| A2 | 2026-10-26 | Develop on a Mac laptop; target ARM64 Linux (Raspberry Pi) for the home server | Windows; Linux mini PC | Mac is in hand; Pi scoped in `cellar-brief.md` section 6 |
| D10 | 2026-10-26 | Framework: SvelteKit with `adapter-node` (resolves O1) | Next.js | Ships far less JavaScript to the phone, form actions give server routes with no client code for the one-handed capture screens, and `adapter-node` runs as a plain Node process on the Pi; Next.js adds React Server Component complexity this app does not need |
| D11 | 2026-10-26 | Database layer: Drizzle ORM with the `better-sqlite3` driver; migrations generated by `drizzle-kit` and committed | Drizzle with Node 24 built-in `node:sqlite`; Prisma; raw SQL | Drizzle is a thin typed layer whose migration files are plain readable SQL. `better-sqlite3` is the most widely used Node SQLite driver and ships prebuilt ARM64 Linux binaries, so it installs on the Pi with no compiler. `node:sqlite` avoids a native add-on but is still marked experimental |
| D12 | 2026-10-26 | Photos: `sharp` resizes each upload to a JPEG of at most 2000 px on the long side; the original is kept under `photos/originals/`. A photo's `taken_at` is the observation time in Phase 1 | No resizing in Phase 1 | `sharp` ships prebuilt ARM64 Linux binaries, so the Pi never serves full-size phone photos. Its prebuilt binaries cannot read HEIC, but iPhone Safari converts photos to JPEG on upload; a HEIC that slips through is kept as is without a resized copy. Reading EXIF dates waits until it is needed |
| D13 | 2026-10-26 | Record ids: short table prefix plus 10 random lowercase characters, e.g. `bat_7k2m9qx4hp` (no 0, 1, i, l, or o) | Prefix plus per-table counter, e.g. `bat-0004`; plain integers | Readable, shows the table at a glance, and never collides when sensor or Mealie imports add rows later. Human numbering lives in batch names such as "Ferment 004" |
| D14 | 2026-10-26 | Ferment reading kinds (resolves O2): `temp_air` (°F), `temp_substrate` (°F, brine or mash), `ph` (pH), `brix` (°Bx), `salinity` (%), `weight` (g), `specific_gravity` (SG) | Brief list 3.7 without specific gravity | Specific gravity is the standard reading for mead, wine, and kombucha. Each reading still stores its own unit |
| D15 | 2026-10-26 | Paprika import unpacked with `fflate` | Node's built-in zlib plus a hand-written zip reader; `adm-zip` | A `.paprikarecipes` file is a zip of gzipped JSON recipes. `fflate` is pure JavaScript, so nothing to compile on the Pi, and handles both layers |
| D16 | 2026-10-26 | Production runs through a small `server.js` that marks requests as plain HTTP; `npm start` runs it with a 500 MB upload limit | Set `ORIGIN` to one fixed address; turn off SvelteKit's cross-site form check | SvelteKit's Node adapter assumes HTTPS and rejected every form post from the phone. One fixed `ORIGIN` would break the other ways of reaching the app (localhost, the laptop's IP, `cellar.local`), and turning the check off would let any web page post into Cellar. If HTTPS is ever added (D2, Tailscale), drop the wrapper |
| D17 | 2026-10-26 | Repeating tasks: tapping Done stamps `done_at` and creates the next task, due the chosen interval after the day it was done. `recurrence` holds `daily`, `weekly`, or `every N days`; empty means a one-off task | One row per job with a last-done date; patterns tied to weekdays | Every check stays in the history as its own row. Counting from the day it was done means a late check never leaves a pile of missed copies. Plain words keep the CSV export readable. Seth uses airlocks, so the examples are airlock top-ups and kahm checks rather than burping |
| D18 | 2026-10-26 | Tasks are due on a date, not a time. `due_at` stores a local date such as `2026-10-27`; `done_at` keeps the full timestamp | Optional time of day; time always | Matches daily and weekly chores, and Today simply shows everything due today or earlier. Less to tap on a phone |
| D19 | 2026-10-26 | Protocols can carry an optional task list in `body_json` (title, first day, repeat, optional last day). It is copied into the batch snapshot with the rest of the protocol, and the tasks are created when the batch is created | Tasks added by hand only | "Check airlock water weekly until day 28" is part of a method and should come with it. The list is optional, so protocols and batches saved before Phase 2 load unchanged |
| D20 | 2026-10-26 | No phone push reminders. The Today screen is the reminder | Web push notifications | Web push requires HTTPS, and Cellar runs on plain HTTP on the home network (D16). Revisit if HTTPS arrives with the Pi (D2) |
| D21 | 2026-10-26 | `task` gains two nullable columns: `repeat_until` (last date a repeat may land on) and `previous_task_id` (the task whose Done created this one). Open tasks on a finished batch are hidden, not deleted | Encode the stop day in the `recurrence` text; delete open tasks when a batch finishes | A separate stop date keeps `recurrence` simple and lets "weekly until day 28" end on its own. The back link lets Undo remove the copy a mistaken Done made. Hiding instead of deleting means reopening a batch brings its tasks back |
